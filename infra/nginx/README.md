## Прод (201.51.29.69, ecomarket-altai.ru)

Три файла ниже — **точные копии** того, что стоит на сервере (сверено `diff` при
коммите). До 11.08.2026 конфиг жил только на сервере, и любая правка терялась
из истории; теперь он в репозитории, но **правится по-прежнему на сервере** —
файлы здесь надо обновлять следом.

| файл в репозитории | путь на сервере |
|---|---|
| `prod-altai.conf` | `/etc/nginx/sites-available/altai.conf` |
| `prod-altai-perf.conf` | `/etc/nginx/conf.d/altai-perf.conf` |
| `prod-altai-security.conf` | `/etc/nginx/snippets/altai-security.conf` |

Порядок правки: `cp` файла на сервер → `nginx -t` → `systemctl reload nginx`.
Перед `cp` — бэкап (`cp -a altai.conf altai.conf.bak-<что>-<дата>`): бэкапы
`*.bak-*` на сервере и есть механизм отката.

### Что делает `prod-altai-perf.conf`

- **gzip** для проксируемых ответов (без `gzip_proxied any` витрина отдавала
  js/css несжатыми — они идут через `proxy_pass`);
- **выбор формата картинки по `Accept`**: `.avif` → `.webp` → исходный
  `.jpg/.png` (`try_files` в `location /img/` и `/uploads/`). Файлы `.avif`
  лежат рядом с оригиналами: для витрины — в git (`apps/frontend/public/img/
  stock/*.jpg.avif`), для товаров — их кладёт Strapi при загрузке фото
  (`apps/strapi/src/index.ts`, `genImageVariants`);
- **микрокеш SSR-страниц** на 30 с. Витрина рендерится на сервере при каждом
  заходе; HTML одинаков для всех (cookie не ставятся, корзина — в localStorage),
  поэтому один рендер обслуживает всех. `/cart`, `/checkout`, `/order/` в кеш
  не попадают. Правка в админке доезжает до посетителя максимум за полминуты
  сверх обычного; сбросить кеш вручную:
  `find /var/cache/nginx/altai_ssr -type f -delete`.

### Ловушки, на которых уже спотыкались

- **`http2` задаётся на первом `listen` для адреса.** Если хотя бы у одного
  `server`-блока для `:443` его нет, nginx берёт опции первого блока — и весь
  сайт работает по HTTP/1.1, даже если у остальных блоков `http2` написан.
  Держать `listen 443 ssl http2;` во ВСЕХ блоках.
- **Подстановка «пусто» в `try_files` ломает цепочку форматов.** Если для
  неподдержанного формата подставлять `""`, первым кандидатом становится сам
  `$uri` — и `.jpg` отдаётся раньше, чем очередь дойдёт до `.webp`. Поэтому в
  `map` вместо пустой строки стоит заведомо несуществующее `.__no`.
- **`/assets/` обязан отдаваться с диска, а не через `proxy_pass`.** Иначе
  каждый js/css идёт через Node и занимает место в кеше SSR.
